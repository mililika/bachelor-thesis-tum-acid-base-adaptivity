\section{Minor issues, not yet actioned}\label{sec:reg-minor}

None of these affects a number or a conclusion in the thesis. They are

\subsection{Experiment repository}

\begin{description}

\item[M1 --- \texttt{findings.md} for X3 is stale.]
\texttt{random\_p\_sweep/findings.md} (21.08, 17:44) documents 63 runs
over $R \in \{1,5,10\}$ and $p \in \{0.05 \dots 0.65\}$ including an
\texttt{--extra-p 0.35,0.65} fallback. The CSVs beside it (22.08,
19:03--19:31) contain 60 runs over $R \in \{1,5,10,15\}$ with no $p =
0.35$ or $0.65$ anywhere. The later run used a different grid and
overwrote the earlier one. \textbf{Its six-row equal-budget table cannot
be reproduced from current data --- four of the six rows cite $p = 0.35$
or $0.65$. Do not transcribe it into the thesis.} Either re-run those
points or rewrite the file against the current grid.

\item[M2 --- three referenced result files do not exist.]
\texttt{random\_p\_sweep\_extra\_seed\{0,1,2\}.csv},
\texttt{random\_p\_sweep\_summary.csv} and
\texttt{random\_vs\_adaptive\_equal\_budget.csv} are all named in
\texttt{findings.md} and absent from \texttt{results/}.

\item[M3 --- javadoc contradicts the code it documents.] Both
\texttt{CriticalDirtyFractionSweepExperiment} and
\texttt{RandomOracleProbabilitySweepExperiment} declare
\texttt{RECONCILER\_VALUES = \{1, 5, 10, 15\}} while their class javadoc
says $R \in \{1, 5, 10\}$ and derives run counts from it: ``$6 \times 3
\times 3 = 54$ runs'' (actually 72) and ``$5 \times 3 \times 3 = 45$
runs'' (actually 60).

\item[M4 --- stale schema caveat.]
\texttt{RandomOracleProbabilitySweepExperiment}'s javadoc explains at
length that X1's CSV ``predates two schema additions'' and that the pure
ACID/BASE anchors are therefore only partly comparable. X1 was re-run at
schema~v3 on 22.08 at 20:24, after both new sweeps. The caveat no longer
applies and the paragraph should be deleted.

\item[M5 --- plot scripts read files that were never generated.]
\texttt{plot\_critical\_dirty\_fraction\_sweep.py} and
\texttt{plot\_random\_p\_sweep.py} both expect \texttt{*\_summary.csv}
merge files; the latter additionally wants the two files listed under M2.
The PNGs currently in \texttt{plots/} date from 21.08 and were rendered
from superseded data. \emph{Author's note: figures are deliberately out
of scope for this pass.}

\item[M6 --- empty directory.]
\texttt{artifacts/experiments/results/} exists and is empty.

\item[M13 --- tick-timeline headers misreport processor counts.] The
header record in \texttt{alpha\_sweep/results/timelines/
timeline\_alpha0.2\_R15\_seed0.jsonl} reports
\texttt{ioProcessors: 15, cpuProcessors: 15}, while the CSV written by
the same run (one minute later) reports 30 and 30, which is the
configured baseline and is consistent across all four sweeps. Exactly
half in both fields, so most likely the header writer reads the wrong
field or a per-pool split rather than the run being misconfigured. Worth
resolving before any timeline-based analysis is attempted --- in
particular before the within-excursion sampling question in
Section~\ref{sec:recovery-status} is investigated, since that analysis
would depend on these files.

\item[M7 --- blocking fraction is not a fraction.]
\texttt{SimulationMetrics.java:93} documents
\texttt{acid\_txn\_blocked\_on\_dirty\_count / acid\_txn\_admitted\_count}
as ``a clean fraction''. It exceeds 1.0 in four cells of the X2 grid
(maximum 1.050 at $R = 10$, $c = 0.20$) because the two counters cover
different populations: \texttt{recordAcidDirtyBlockStart} fires during
lock acquisition
(\texttt{TransactionLockCoordinator.java:178}) while
\texttt{incrementAcidTxnAdmitted} fires only on successful admission.
Either widen the denominator to attempted admissions or drop the
fraction. Cross-referenced from Section~\ref{sec:x2-mechanism}.

\end{description}

\section{Checks performed that found nothing}\label{sec:reg-clean}

Recorded because a negative check is evidence too.

\begin{itemize}
\item Every non-ACID-fraction column of the old X1 table reproduces
exactly against the 22.08 re-run: throughput, switch counts, $p_{50}$,
$p_{95}$, \texttt{started\_total}, \texttt{aborted\_total}.
\item The X5 $\alpha = 0$ rows equal the X1 BASE rows to five
significant figures at all four values of $R$.
\item Configuration columns (\texttt{cfg\_*}) are identical across X2 and
X3 apart from the swept parameter and the oracle type, confirming the
two sweeps share the baseline as intended.
\item All three seeds are present in all four sweeps, with no missing
cells anywhere in any grid.
\item \texttt{aborted\_base} is zero in every row of every sweep,
consistent with O5.
\item Degenerate cells in X2 match the corresponding BASE rows of X1 to
the digit, in every seed.
\end{itemize}
